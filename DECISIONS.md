# DECISIONS.md

Ambiguities resolved during the unattended build. Format: date · decision · why. Every choice that changes a number is configurable in `config/game.ts`.

| Date | Decision | Why |
|---|---|---|
| 2026-11-04 | Game config lives at `config/game.ts` (not `src/config/game.config.ts` as GAME.md says). | The build brief names `config/game.ts`; the repo has no `src/` dir. Same zod validation and `GAME_CONFIG_PATH` override apply. |
| 2026-11-04 | Next.js 15.5 (App Router), React 19.2, TypeScript 5.9 strict, Tailwind v4 (CSS-first `@theme`). | Latest stable line that Auth.js v5 beta supports; TS 7 is too new for Next 15 tooling. Tailwind v4 theme tokens are declared in CSS `@theme`, which is the v4 form of "theme extensions". |
| 2026-11-04 | Prisma 7 (`prisma-client` generator, driver adapters). With no `DATABASE_URL` the app uses embedded PGlite through `pglite-prisma-adapter`; with `DATABASE_URL` it uses `@prisma/adapter-pg`. | Zero-setup local runs with the same Postgres dialect as Neon. |
| 2026-11-04 | Migrations are SQL files generated by `prisma migrate diff` and committed under `prisma/migrations/*/migration.sql`. A tiny runner (`lib/db/migrate.ts`) applies them to PGlite; on Neon use `prisma migrate deploy`. | Prisma CLI cannot talk to an in-process PGlite. The SQL files are the same in both paths. |
| 2026-11-04 | Playwright pinned to 1.63.0. | Matches the Chromium build pre-installed in the build machine, so e2e runs offline. |
| 2026-11-04 | Cards are rendered with `next/og` (bundled Satori + resvg) in the Node runtime with self-hosted `@fontsource` WOFF fonts. | No external font or CDN request at runtime. |
| 2026-11-04 | Sector `drift`, `volatility`, `newsSensitivity` defaults (GAME.md gives only pool sizes): drift 0 to 0.0004 per tick, volatility 0.004 to 0.007, sensitivity 0.8 to 1.3. | Keeps pools inside the `[0.5, 2.0]` clamp over a season while still moving week to week. All in `config.sectors`. |
| 2026-11-04 | New companies start with `company.startingCash = §400,000` minted with reason `angel` (cap table 80% founder, 10% angels, 10% pool, as in the TermSheet mockup). | GAME.md lists no mint source for a company's first cash, but burn starts on tick one. The mint is logged like every other source. |
| 2026-11-04 | Unpaid opex becomes company `debt` (a number, not scrip). "Cash below 0" in GAME.md 8.6 means `debt > 0`; new cash pays debt to `BURN` first. | The ledger forbids negative balances; this keeps the invariant exact. |
| 2026-11-04 | Ambition "pivot tolerance" maps to a pivot threshold adjustment (`ambition.pivotThresholdAdj`): bootstrap −0.10, lifestyle 0, moonshot +0.15 until runway < 30 days. "Hire bias" high = +1 hire on a hiring week (`ambition.hireBias`). | GAME.md gives qualitative labels only. |
| 2026-11-04 | RNG domains extended with `stats`, `names`, `odds`, `season`, `crash` (still substreams of the season seed). Beta(2,2) is drawn as the median of three uniforms. | Needed for hidden stat draws, name generation and forward odds without sharing streams. Median-of-3 is exactly Beta(2,2). |
| 2026-11-04 | Persistence model: mutable entities (season, sectors, founders, funds, companies, offers, deals, exit offers, decisions, feuds) keep indexed columns plus the full engine object in a `state` JSON column; logs (ledger entries, marks, posts, pitches, events, ticks, notifications, drafts, demo days) are append-only tables. A tick loads the world, runs pure rules in memory, then saves in one transaction with an optimistic `Season.version` check. | Keeps `lib/rules` pure and the tick deterministic, while the DB stays queryable for screens. JSON round-trips of doubles are exact. |
| 2026-11-04 | `pnpm db:migration <name>` diffs `prisma/migrations/schema.snapshot.prisma` against the schema with `prisma migrate diff` (no DB needed). | Works without a shadow database. |
| 2026-11-04 | Thesis weight renormalisation projects onto the clamped simplex (`sum(clamp(w + t)) = 1` by bisection) instead of a single clamp-then-renormalise. | GAME.md's "renormalise, clamp, renormalise again" can push weights back outside `[weightMin, weightMax]`; the projection always satisfies both the sum and the clamps. |
| 2026-11-04 | The mock judge scores the rubric from public pitch facts (revenue run-rate, 7-day growth, headcount, moat, sector heat, founder reputation) plus a hash jitter, never from hidden `q`. Hidden quality reaches the panel only through real traction. | GAME.md says the mock returns rubric and interest "from a hash of the input"; pure hash noise would make company quality irrelevant to funding. |
| 2026-11-04 | `AnthropicProvider` uses the official `@anthropic-ai/sdk` with `claude-opus-5-5` (override with `ANTHROPIC_MODEL`), `effort: low`, no tools, server-side refusal fallbacks (`fallbacks: "default"`). A refusal, error, invalid JSON or schema failure retries once, then the deterministic mock answers. | Matches the brief: no tools, zod-validated structured output, mock fallback. |
| 2026-11-04 | NPC pitch panels draw only NPC funds; each fund sits on at most `vc.dealFlowPerTick` panels per tick. Player-owned funds get their deal flow as a "take 1 of 3 meetings" decision; the chosen meeting resolves as a one-seat pitch. | Implements GAME.md 6.6 without letting a player fund hold up an NPC company's pitch. |
| 2026-11-04 | Per-VC red flags for the fit formula are the judge's red flags for that VC (validated against the enum). | GAME.md 6.4 says red flags come from the judge's enum list. |
| 2026-11-04 | When a user already has `decision.maxOpenPerUser` open calls, a new decision is recorded and immediately resolved by its default (`by: "default"`, outcome "Inbox full"). The underlying offer still runs to its own lapse. | GAME.md caps open decisions but does not say what happens to the overflow. |
| 2026-11-04 | NPC founders wait one tick for competing offers, then take the best by pre-money (bootstrap avoids board seats); moonshots counter once at `negotiation.npcCounterRatio` (1.15x pre). | "NPC-vs-NPC negotiation resolves automatically ... with ambition-based counter behaviour". |
| 2026-11-04 | Card ids are `sha256(seasonSeed | card | kind | refId)` truncated to 20 hex chars (80 bits). | Unguessable while the seed is secret and deterministic for the seeded world. |
| 2026-11-04 | After a round closes the company advances one stage (preseed → seed → Series A) and its next ask is the midpoint of that stage's capital range. | GAME.md does not define stage progression. |
| 2026-11-04 | `traction` starts at `company.tractionStart = 0.3` and ramps toward 1 by `company.tractionRamp = 0.03` per tick (faster with marketing). It multiplies demand units. Pivots cut it by 30%. | GAME.md has traction in company state and the pivot rule but no formula; a ramp gives young companies visible early growth. |
| 2026-11-04 | Fundraising: one pitch every `fundraise.pitchEveryTicks = 3` ticks while a window is open, at most `fundraise.maxPitches`, then a `fundraise.windowCooldownTicks` pause. Moonshots open a window when runway is under 2x the trigger and they have not raised at this stage recently ("stage gate"). | GAME.md gives the trigger and caps, not the cadence. |
| 2026-11-04 | Outcome odds use a reduced-form forward model of one company (revenue random walk with its growth, cash vs burn with a chance to raise, acquirer bids, mark drift), 200 runs seeded by `(companyId, tick)`, computed on demand for the company page. A company that ends the horizon small but self-sustaining counts toward "Zombie" (the ladder has five rungs; "operating" is not shown). | Re-running the whole world 200 times per company per tick is too slow for a page view. |
| 2026-11-04 | On acquisition the company's remaining cash moves to the acquirer treasury (`acquisition_cash`), the exit fee is burned from the treasury, funds get `ownership x (price - fee)`, the player founder's wallet gets the capped sliver. | Keeps conservation exact and matches GAME.md 11 "Exits". |
| 2026-11-04 | Small-sector bands rank companies by their raw percentile composite; the below-median growth cap still applies afterwards. | GAME.md says "use bands instead of percentiles" without naming the ranking key. |
| 2026-11-04 | A "markup" thesis-drift event fires when a later round prices a company at `pre / entry post >= vc.drift.markupMinMultiple` (1.5x) or below 1x. Existing pro-rata holders follow on with `share x new check` (rounded to §50K) at the round's post-money when the company is in the top half of its sector and the fund has the dry powder. | GAME.md lists markups as drift events and follow-ons as fund behaviour without thresholds. |
| 2026-11-04 | Fund reputation and founder reputation update once per day (every `ticks.perDay` ticks), as GAME.md 12 says "daily". | — |
| 2026-11-04 | Acquisition bids: `exit.bidProbPerTick` is applied once per eligible company per tick and a random NPC acquirer is the bidder (not once per acquirer). | Per-acquirer rolls with three acquirers sold almost every top-half company within a season (54 of 72 in a test run); the per-company reading keeps exits rare enough to be jackpots. |
| 2026-11-04 | Mock judge calibration: traction leans on the public sector-rank percentile (shown on the company page) and panel interest for established companies follows `-0.06 + 0.78 x pct^1.6 + growth`; brand-new companies are judged on the idea (`Q - 0.16`). `company.startingCash` is §300K and `fundraise.windowCooldownTicks` 21. | With GAME.md's 6 pitches x 3 VCs per window, anything above ~3% P(offer) funds every laggard and nobody dies. These are mock/tuning choices, not GAME formulas. |
| 2026-11-04 | Demo Day is the evening tick of every 7th day (`tick % 21 == 0`): the season is defined to start on a Saturday so that tick is Friday. | Ticks are numbered, not dated, so the engine stays deterministic. |
| 2026-11-04 | Idle NPC founders whose company died or exited restart with a new company (up to `world.restartsPerWeek` per week while live companies < `world.minLiveCompanies`). | Keeps the floor populated over a 270-tick season. |
| 2026-11-04 | Notifications: same-type items within a tick are batched ("(+N more)"), capped at `notifications.maxPerDay` per user per game day; pushes are skipped in quiet hours (game time zone) but the inbox keeps them. | GAME.md 16. User-local time zones are not collected in v1. |
